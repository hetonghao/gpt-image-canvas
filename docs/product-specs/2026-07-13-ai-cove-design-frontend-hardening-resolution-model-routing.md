# AI Cove Design 前端质量收口与分辨率模型路由

## Problem Statement

AI Cove Design 已具备画布、图库、提示词池、生成历史、Agent 与生成服务配置等核心能力，但现有前端在资产可靠性、状态表达、键盘操作、移动端细节、性能和设计系统一致性上存在明显断层。真实页面审查发现，历史资产可能在画布、图库和参考图流程中显示为破图；不可读取的图片仍可能被标记为“参考图已就绪”；失败的生成历史缺少具体失败原因。部分页面还存在错误状态压过主要内容、空态文案与真实场景不符、空图库仍可进入导出模式、嵌入路由参数丢失、Dialog 焦点逃逸、Tabs 键盘行为不完整、移动端触控目标和中文排版不稳定等问题。

代码层面同样缺少可持续保障：颜色与控件契约分散，Dialog、Tabs、搜索框和状态提示没有可靠的共享行为层；主画布模块承担过多状态与副作用；大量 UI 冒烟测试只匹配源码文本，无法证明用户实际可操作。Prompt Pool 还会首屏急切加载大量远程图片，放大移动网络下的等待成本。

与此同时，现有尺寸系统已经支持 1K、2K、4K，但生成服务配置只有一个默认图片模型。用户无法为 2K、4K 选择专用模型，也无法在专用模型缺失时理解实际使用了什么模型。需要在不增加额外凭据、不阻断生成流程的前提下，新增可选的 2K、4K 模型配置，并由服务端按请求尺寸统一解析实际模型。1K 继续使用现有默认模型；2K、4K 未配置专用模型时，必须明确但安静地回退到当前生成源的默认模型。

## Solution

以“可靠、可解释、不中断创作”为原则，分四个阶段完成前端质量收口。

第一阶段先修复资产链路与错误状态。历史资产的本地可读性是画布、图库和参考图状态的唯一依据；图片加载或解码失败时，不得显示为可用参考图。失败生成记录必须保留可操作的错误原因。页面级错误、局部错误、空数据和搜索无结果使用不同的状态层级，避免次要功能失败覆盖主要内容。

第二阶段收口交互正确性和响应式行为。嵌入模式的路由参数在内部导航后保持不丢失；Dialog 具备完整焦点管理；Tabs 支持标准键盘操作；搜索框的视觉区域与真实点击区域一致；移动端导航、提示条和中文标签不裁切、不异常断词；侧车 iframe 不再产生固定宽度损失。Prompt Pool 图片改为按视口懒加载和异步解码。

第三阶段增加分辨率模型路由。现有默认图片模型在界面中明确为“默认图片模型（1K）”，保持必填和原有行为。在同一图片服务区域增加“高分辨率模型（可选）”，包含 2K 模型和 4K 模型两个可清空的选择项。空值直接显示“跟随默认图片模型（当前：模型名）”，不使用空白占位、不增加开关、不增加独立 API Key、Base URL 或超时配置。

用户选择 2K 或 4K 尺寸时，服务端根据请求尺寸和当前活动生成源解析实际模型：专用模型存在则使用专用模型；不存在则直接回退到该生成源的默认模型。回退不跨生成源、不更换 API Key、不改变 source order，也不偷偷把请求尺寸改回 1K。画布尺寸区域持续显示一条低打扰的内联提示，例如“未配置 4K 专用模型，本次将使用默认图片模型 gpt-image-2；尺寸仍按 4K 请求。”可编辑的生成源提供“配置高分辨率模型”入口；只读生成源只提供“查看当前生成源”。生成按钮保持可用，不使用 Toast 或生成前确认弹窗。

每次生成记录都保存请求分辨率层级、请求尺寸、实际模型、生成源以及是否发生模型回退。生成成功、失败、取消或中断后，历史记录都能说明本次请求实际走了哪条路，避免把提示词中的“4K”或尺寸标签误解为供应商一定返回严格物理分辨率。实际输出像素仍以生成资产元数据为准。

第四阶段统一设计系统、共享交互契约与测试接缝。在不改变现有 warm paper、dark ink、copper action、teal focus 品牌方向的前提下，优先把本规格触及的 Dialog、Tabs、SearchField、Alert、Button、EmptyState 和图片状态收口为共享组件；逐步减少硬编码颜色和跨页面重复样式；按画布、生成、历史、配置、图库和 Agent 职责拆分巨型状态内核。测试从源码字符串匹配转向纯路由决策测试、API 往返测试、真实生成调用验证、渲染行为测试和关键浏览器流程。

## User Stories

1. 作为创作者，我希望历史图片在画布和图库中可靠显示，以便继续查看、编辑和复用过去的作品。
2. 作为创作者，我希望破损或不可读取的图片被明确标记为不可用，以免把无效资产误当成正常输出。
3. 作为创作者，我希望只有成功加载并可解码的图片才显示“参考图已就绪”，以免提交一个实际不可用的参考图任务。
4. 作为创作者，我希望参考图不可用时看到恢复入口，以便重新上传、重新选择或定位原始资产。
5. 作为创作者，我希望失败的生成历史显示具体失败原因，以便判断是权限、额度、超时、模型还是资产问题。
6. 作为创作者，我希望局部功能失败不会覆盖整个页面的主要内容，以便在收藏、云备份等次要能力异常时继续工作。
7. 作为提示词池用户，我希望搜索无结果时看到与筛选条件相关的文案，以免误以为项目数据源缺失。
8. 作为提示词池用户，我希望收藏加载失败被显示为局部状态，以便继续浏览和使用已经加载成功的提示词。
9. 作为图库用户，我希望没有作品时不能进入无意义的导出模式，以免面对一组全部禁用的操作。
10. 作为图库用户，我希望进入任何模式后仍能看到当前加载错误，以免错误被工具栏或选择状态隐藏。
11. 作为嵌入 AI Cove Design 的用户，我希望内部导航保留嵌入模式参数，以免刷新后意外进入独立站模式。
12. 作为键盘用户，我希望打开配置 Dialog 后焦点进入弹窗并留在弹窗内，以便不触发背景页面控件。
13. 作为键盘用户，我希望关闭 Dialog 后焦点稳定返回触发按钮，以便继续原来的操作路径。
14. 作为键盘用户，我希望配置 Tabs 支持左右方向键、Home 和 End，以便按标准 ARIA Tabs 模式导航。
15. 作为移动端用户，我希望导航、搜索、图标按钮和关闭按钮拥有足够大的触控区域，以免频繁误触。
16. 作为移动端中文用户，我希望标签、状态和警告文案按语义换行，不裁切图标、不把短词拆成孤立单字。
17. 作为弱视用户，我希望辅助错误文本和占位文本达到可读对比度，以便在浅色纸张背景上辨认信息。
18. 作为慢网络用户，我希望提示词池只加载即将进入视口的图片，以便更快看到可操作的页面内容。
19. 作为创作者，我希望各页面使用一致的加载、空态、错误和按钮语言，以便快速理解当前状态。
20. 作为管理员，我希望继续用现有默认图片模型处理 1K 请求，以便升级后不改变当前生产行为。
21. 作为管理员，我希望可以为 2K 配置一个可选专用模型，以便把 2K 请求路由到更合适的模型。
22. 作为管理员，我希望可以为 4K 配置一个可选专用模型，以便把 4K 请求路由到更合适的模型。
23. 作为管理员，我希望 2K、4K 模型与默认模型共用同一 API Key、Base URL 和超时设置，以免维护重复凭据。
24. 作为管理员，我希望清空 2K 或 4K 模型后立即恢复“跟随默认模型”，以便安全撤销专用路由。
25. 作为管理员，我希望默认模型变化后，空置的 2K、4K 字段自动显示新的跟随目标，以免保存过时的复制值。
26. 作为管理员，我希望同一个模型可以同时用于多个分辨率层级，以便兼容只提供一个通用模型的供应商。
27. 作为创作者，我希望选择 2K 时优先使用已配置的 2K 模型，以便获得预期的高分辨率能力。
28. 作为创作者，我希望选择 4K 时优先使用已配置的 4K 模型，以便获得预期的高分辨率能力。
29. 作为创作者，我希望 2K 专用模型未配置时仍可直接生成，以便配置不完整不会阻断工作。
30. 作为创作者，我希望 4K 专用模型未配置时仍可直接生成，以便配置不完整不会阻断工作。
31. 作为创作者，我希望模型回退发生时在尺寸区域持续看到提示，以便在提交前理解实际路由。
32. 作为创作者，我希望模型回退不弹出确认框或一次性 Toast，以便生成流程保持连续。
33. 作为创作者，我希望模型回退后仍按我选择的 2K 或 4K 尺寸发起请求，以免系统静默更改构图尺寸。
34. 作为创作者，我希望历史记录显示请求层级、实际模型和是否回退，以便复盘生成质量和成本。
35. 作为创作者，我希望失败记录也显示已解析的模型和生成源，以便定位上游错误。
36. 作为 Agent 用户，我希望 Agent 计划中不同尺寸的任务分别解析模型，以便一个计划内的 1K、2K、4K Job 使用正确路由。
37. 作为系统维护者，我希望模型路由由服务端统一决定，以免 Canvas、Agent 和未来入口产生不同判断。
38. 作为系统维护者，我希望高分辨率模型缺失时只在当前活动生成源内回退，以免系统静默切换凭据或供应商。
39. 作为系统维护者，我希望旧配置和旧数据库在升级后继续工作，以便未配置高分辨率模型的用户无感迁移。
40. 作为系统维护者，我希望关键 UI 流程由真实渲染和浏览器行为测试保护，以免源码文本测试在界面实际失效时仍然通过。

## Implementation Decisions

- 本规格按“资产链路 RCA 与恢复、行为正确性、分辨率模型路由、设计系统与架构收口”的顺序实施。前一阶段的阻断项未关闭前，不用纯视觉润色掩盖状态或数据问题。
- 历史资产以本地文件可读取、预览接口可返回、浏览器可加载和解码为可用条件。Canvas、Gallery、详情页和参考图入口共享同一资产状态，不各自推断。
- 不可读取的资产显示稳定占位、错误说明和恢复操作，不显示浏览器原生破图图标或悬浮 alt 文本。参考图的 ready 状态必须依赖成功加载/解码，而不是仅依赖已有 URL 或资产 ID。
- 失败生成记录保留经过安全清理的具体错误原因。页面必须区分整页失败、局部子系统失败、真正空数据和筛选无结果；已有主要数据时，局部错误使用邻近内容的非阻断提示。
- Gallery 在零作品时不进入导出选择模式；进入任何选择模式都不得隐藏加载或权限错误。Prompt Pool 搜索无结果文案引用当前关键词和筛选条件，不使用“内置 JSON 尚不可用”等数据源缺失文案。
- 嵌入模式和其他运行时查询参数在应用内部路由时保持。导航只更新目标路径需要变化的部分，不丢弃未知但有效的查询参数。
- Dialog 使用完整的模态焦点契约：打开时设置确定的初始焦点，Tab/Shift+Tab 不离开弹窗，背景不可交互，Escape 关闭，关闭后优先恢复到触发控件；触发控件已消失时使用可预测的安全回退。
- Tabs 遵守标准键盘模式：仅活动 Tab 在自然 Tab 顺序中，ArrowLeft/ArrowRight 循环切换，Home/End 跳到首尾，并保持选中状态、焦点和面板内容同步。移动端不得依靠任意断词压缩固定列宽。
- SearchField 的完整可见外壳都是输入命中区域。移动端最小触控目标为 44×44 CSS 像素，紧凑桌面目标至少为 40×40 CSS 像素；Pool 和 Gallery 复用同一行为契约。
- 移动端 Alert 为图标保留固定空间，正文采用适合 CJK 的正常换行，不使用会把短词拆成单字的任意断词。侧车 iframe 作为块级元素占满容器，消除所有视口固定出现的额外滚动槽。
- Prompt Pool 图片默认使用懒加载和异步解码，并限制首屏预取范围。不得一次性以 eager/sync 方式请求固定数量的远程图片；滚动接近视口时再加载后续媒体。
- 现有单一图片模型在契约和界面中继续作为默认模型，并在用户可见文案中标记为“默认图片模型（1K）”。该字段保持必填；原有配置升级后行为不变。
- 本地 OpenAI-compatible 图片源新增两个可空字段：2K 模型和 4K 模型。它们与默认模型共用 API Key、API Key ID、Base URL、超时和 source order，不引入单独凭据、启用开关或嵌套配置卡片。
- 配置界面在默认模型之后使用一个轻量分组“高分辨率模型（可选）”。桌面端两个选择框可并排，移动端纵向排列。每个选择框的空选项显示“跟随默认图片模型（当前：<模型名>）”；清空后持久化为空值，而不是复制默认模型字符串。
- 保存请求中省略高分辨率字段表示保留现值，显式空字符串表示清除并恢复跟随默认模型；读取响应返回规范化后的空值和服务端计算出的跟随结果。已保存但暂时不在模型列表中的模型 ID 不得被静默删除。
- 高分辨率配置归属于当前生成源。活动源是本地可编辑源时，使用本地 1K/2K/4K 配置；活动源是只读环境源或 Codex 源时，使用该源可提供的模型信息。一个源缺少专用模型时只回退到同一源的默认模型，绝不跨到较低优先级源借用模型或凭据。
- 本规格不要求新增环境变量或 Codex 专用的 2K、4K 配置入口。只读源没有专用模型时按默认模型回退；未来若增加只读源的分层配置，也必须复用同一解析契约。
- 分辨率层级继续由现有尺寸规则计算：最长边达到 2048 进入 2K，达到 3840 进入 4K，其余为 1K。客户端不得另建一套阈值或从标签文本推断层级。
- 服务端提供唯一的“请求尺寸层级到实际模型”解析接缝。1K 始终解析到默认模型；2K 解析到 2K 专用模型，否则回退默认模型；4K 解析到 4K 专用模型，否则直接回退默认模型。4K 不自动借用 2K 模型。
- 模型回退只改变实际模型，不修改用户请求的宽高、质量、输出格式、数量、提示词或参考图。供应商最终返回的实际像素尺寸继续从资产元数据读取，不能仅凭请求标签宣称“真实 4K”。
- 手动画布生成、参考图编辑、后台任务和 Agent 多 Job 执行全部复用服务端解析接缝。Agent 计划可能包含不同尺寸的 Job，因此模型必须按 Job 解析，不能只在整份计划开始时固定一次模型。
- 生成记录新增请求分辨率层级、实际模型、生成源和模型回退状态。路由决策应在调用上游前写入或更新，使成功、失败、取消和中断记录都可解释；旧记录允许这些字段为空，并以“旧记录未保存模型路由信息”展示。
- Canvas 尺寸区仅在用户选择 2K/4K 且当前路由将回退时显示常驻内联提示。提示使用图标、文字和低强调 warning/info 颜色，不使用 Toast、阻断弹窗或禁用生成按钮。
- 内联提示的操作根据生成源能力变化：可编辑源显示“配置高分辨率模型”并打开图片模型配置区域；只读源显示“查看当前生成源”，不得承诺用户可以在当前页面修改只读配置。
- 历史和任务详情以紧凑元数据显示“请求：4K 3840×2160”“实际模型：<模型名>”“已回退到默认模型”等信息。回退不能只用颜色表达；失败卡同时展示安全的上游错误原因。
- 设计系统保持现有 paper、ink、copper、teal 方向。本规格触及的状态颜色、边框、焦点、间距和触控尺寸优先使用统一 token；不在同一轮全面重写所有历史 CSS。
- 优先建立共享 Dialog、Tabs、SearchField、Alert、Button、EmptyState 和 AssetState 契约，再迁移本规格触及的页面。共享层负责语义、键盘、焦点、尺寸和状态，不把所有视觉变体塞入单个巨型组件。
- 主画布内核按稳定领域职责拆分状态和副作用：运行时路由、生成任务、资产/历史、Provider 配置、Agent 和画布桥接分别拥有清晰边界。拆分以减少跨域状态耦合为目标，不以文件行数本身作为验收条件。
- 加载语言在 Canvas、Pool、Gallery 和配置页统一使用稳定骨架或明确的局部加载状态，避免空白画布与居中加载卡在不同路由间无规则切换。

## Testing Decisions

- 好测试验证用户可观察行为和服务端最终决策，不匹配实现文件中的字符串、CSS 类名或 Hook 数量。源码形态检查只能作为补充，不能代替渲染、键盘和真实请求测试。
- 最高优先级测试接缝是一个共享的纯模型解析器。覆盖 1K 使用默认模型、2K 使用专用模型、2K 缺失时回退默认模型、4K 使用专用模型、4K 缺失时直接回退默认模型，以及 4K 不借用 2K 模型。
- Provider 配置 API 测试覆盖旧请求兼容、2K/4K 保存与读取、空字符串清除、字段省略保留、模型 ID 前后空白规范化、SQLite 可空列迁移、按用户隔离和密钥掩码不变。
- 生成服务测试必须观察最终发送给上游 provider 的 model 值，而不是只测试配置对象。手动生成、参考图编辑和 Agent 多 Job 至少各覆盖一个分辨率路由场景。
- 生成记录测试覆盖请求层级、请求尺寸、实际模型、生成源和回退状态的持久化；成功、上游失败、取消和服务重启中断都保留可解释路由信息。旧记录缺少新字段时仍能读取。
- 配置页渲染测试覆盖默认模型必填、2K/4K 可选、动态“跟随默认模型”文案、清空、保存失败、未知已保存模型，以及桌面并排/移动堆叠布局。
- Canvas 浏览器测试覆盖选择 2K/4K 时的回退提示、配置入口、生成按钮不被阻断、已配置专用模型时提示消失，以及只读源显示“查看当前生成源”。
- Dialog 浏览器测试覆盖初始焦点、正反向 Tab 循环、背景不可聚焦、Escape 关闭和焦点恢复。Tabs 测试覆盖 ArrowLeft、ArrowRight、Home、End 与移动端标签完整性。
- 路由测试覆盖嵌入模式参数经过 Canvas、Pool、Gallery 等内部导航后仍然存在，并覆盖刷新后的模式恢复。
- Asset 浏览器测试使用可读取图片、404 图片、无法解码图片和已删除本地文件，验证 Canvas、Gallery、详情页与参考图 ready 状态一致。
- Prompt Pool 测试观察真实图片请求数量和加载属性，确认首屏不再固定急切请求 24 张远程图片，并在滚动接近视口后加载后续图片。
- Pool/Gallery 状态测试覆盖主要数据成功但收藏失败、搜索无结果、真正空数据、整页加载失败、零作品导出入口和选择模式下错误可见性。
- 响应式浏览器覆盖至少 375、768、1280 三档；验证 44px 移动触控目标、搜索输入完整命中区、Provider Tabs、Canvas Alert、导航和 iframe 宽度。辅助文本对比度至少达到 WCAG AA。
- 视觉回归重点覆盖配置页图片模型区域、Canvas 尺寸回退提示、失败历史卡、破损资产占位、Prompt Pool 局部错误和 Gallery 空态，不把截图测试用于掩盖缺失的交互断言。
- 验收时必须在本地真实浏览器完成桌面和移动人工 QA，并在可登录的 AI Cove 嵌入路径验证至少一次配置读取、分辨率选择、生成提交和历史解释链路。若外部模型调用不可用，必须使用可观察最终 model 参数的受控 provider 替身完成端到端验证。

## Out of Scope

- 不新增新的尺寸预设、分辨率阈值或自定义尺寸系统。
- 不为 2K、4K 增加独立 API Key、Base URL、超时、source order、计费账户或启用开关。
- 不在本规格中新增环境变量或 Codex 专用高分辨率模型配置入口。
- 不在专用模型缺失时自动把 4K 路由到 2K 模型。
- 不根据提示词中出现的“2K”“4K”决定模型；只依据结构化请求尺寸。
- 不承诺供应商一定返回严格 2K/4K 物理像素；实际结果以资产元数据为准。
- 不更改 Provider 优先级，不在回退时静默切换生成源、凭据或供应商。
- 不重做品牌方向，不引入通用 SaaS 蓝紫渐变、玻璃拟态、装饰性动效或新的前端动画依赖。
- 不在本规格中一次性重写所有 CSS、所有页面或完整替换画布技术栈。
- 不处理公共付费发布、模型定价、额度策略、生产发布和 lock 更新。

## Further Notes

- 当前尺寸契约已经具备 1K、2K、4K 类型和基于最长边的层级计算，本规格复用该能力，不创建重复概念。
- 当前 Provider 顺序为环境 OpenAI-compatible、本地 OpenAI-compatible、Codex。高分辨率模型回退必须遵守这个边界：先选活动源，再在该源内解析模型。
- 当前生成记录只保存请求尺寸等信息，未保存实际模型与回退事实；这是本次可解释性改造的必要数据基础。
- 本规格汇总了代码审查、桌面真实页面审查和 375/768/1280 响应式及无障碍审查。已确认的首要风险是历史资产破损与错误 ready 状态，其优先级高于纯视觉润色。
- 建议按阶段形成可独立验证、可回滚的提交。资产链路根因尚未通过本规格预设为某一种存储故障，实施时应先用真实路由、数据库记录和文件存在性完成 RCA，再选择最小修复。
- 本轮只定义规格和验收边界，不修改产品代码、不执行生产发布。
